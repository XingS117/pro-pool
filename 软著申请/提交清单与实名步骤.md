## 第七部分：微信小游戏宿主兼容处理记录（已验证）

微信小游戏运行时与浏览器差异较大，本次已逐项处理并以模拟运行时测试验证（tests/mg_runtime.test.js，13 项断言全绿）：

| 宿主差异 | 处理方式 |
|---|---|
| 主线程 2D Canvas 不支持 ctx.createImageData | 台呢纹理改为「优先 ImageData、不可用则纯绘制降级」（渐变底色 + 低频色斑 + 交织网格 + 高频噪点），两平台视觉一致 |
| canvas 无 DOM 盒模型 | 适配层为 canvas 注入 getBoundingClientRect，返回与屏幕尺寸一致的矩形 |
| 无 document.body.classList | 适配层提供完整的 classList（add/remove/toggle/contains）实现 |
| 无 window.matchMedia / innerWidth / innerHeight | 适配层按 wx.getSystemInfoSync 提供；matchMedia 以 pointer:coarse 粗指针判定 |
| 无 window.AudioContext | 映射为 wx.createWebAudioContext() |
| 无 atob | 适配层内置 base64 解码（音频内嵌采样解码需要） |
| 无 localStorage / sessionStorage | 映射为 wx.setStorageSync / getStorageSync |
| 无 requestAnimationFrame | 以 setTimeout(16ms) 驱动 |
| 分享能力缺失 | 调用 wx.showShareMenu 与 wx.onShareAppMessage 注册转发卡片 |
| 离屏画布创建 | 渲染器的离屏画布经 document.createElement('canvas') 统一走 wx.createCanvas()，并自动补齐像素 API 与盒模型 |

以上改动仅涉及适配层与一处渲染器降级分支，不改变物理、规则与 AI 逻辑；网页版全量 31 套测试全绿。

**开发者工具实测提醒**：导入后请在真机预览一次，重点确认台呢纹理（降级路径）与号码清晰度。

### 小游戏注册要点（依据官方《类目设置》文档，2026-04-01 更新）

1. **一级类目固定为「游戏」**：注册时勾选，**不支持修改、不支持删除**；选错只能重新注册账号。
2. **二级类目在发布前可改，发布后不可改**；三级类目可在资质管理中修改，但需重新过资质审核并发布新版本。
3. **个人主体不支持「文化互动、角色类、牌类」**三种二级类目。台球属「休闲」类，**个人主体可选**。
4. 二级游戏类目须与实际内容相符，否则提审版本会被驳回 —— 本作为八球台球，应选**休闲类**，不可选角色类或棋牌类。
5. 操作路径：首页「小程序类目 → 去补充 → 添加类目」，需管理员微信扫码验证。
